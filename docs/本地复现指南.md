# KServe 本地复现指南

> 一套在 Windows 上把 **KServe v0.17.0** 在本地跑通（`READY=True` + 真实 HTTP 推理返回）的自动化脚本。
> 包含两个版本的复现路径、六个已踩过的坑，以及全部中间产物。

---

## 一、这个包解决什么问题

KServe 是跑在 Kubernetes 上的 AI 模型服务化平台（CRD 叫 `InferenceService`）。
官方文档的安装步骤是十几条散命令，手工操作时最容易卡在两处：

1. **模型投递失败** → `storage-initializer` 初始化容器反复崩溃 → `READY` 永远不变成 `True`
2. **容器镜像拉不下来** → 国内访问 Docker Hub 被污染 → `ErrImagePull` → 同样卡死

这两个坑都不是配置写得对不对的问题，而是**认知盲区**，本包把解法固化成了脚本。

## 三、前置条件

| 工具 | 版本 | 装法 |
|---|---|---|
| Docker Desktop | 任意近期版本 | 官网下载，**per-user 安装**即可；勾选 WSL2 后端 |
| kubectl | v1.30.0 | `https://dl.k8s.io/release/v1.30.0/bin/windows/amd64/kubectl.exe` |
| kind | v0.23.0 | `https://kind.sigs.k8s.io/dl/v0.23.0/kind-windows-amd64` |
| Helm | v3.15.2 | `https://get.helm.sh/helm-v3.15.2-windows-amd64.zip` |

三个 exe 放在 **`%USERPROFILE%\.local\bin\`** 下最省事（脚本会自动去这个目录找，
找不到也会退回到系统 PATH）。示例：

```powershell
mkdir "$HOME\.local\bin" -Force
cd "$HOME\.local\bin"
curl.exe -LO "https://dl.k8s.io/release/v1.30.0/bin/windows/amd64/kubectl.exe"
curl.exe -Lo ./kind.exe https://kind.sigs.k8s.io/dl/v0.23.0/kind-windows-amd64
curl.exe -LO https://get.helm.sh/helm-v3.15.2-windows-amd64.zip
Expand-Archive -Path helm-v3.15.2-windows-amd64.zip -DestinationPath .
Move-Item .\windows-amd64\helm.exe .\helm.exe
```

> **WSL 不需要单独装发行版。** Docker Desktop 的 Linux 容器后端自带 WSL2 环境，
> kind 集群跑在 Docker 容器里，全流程不需要进入 Linux。

## 四、三分钟跑通（版本一 · 直连）

### 方式 A：双击

资源管理器里双击 **`运行-PS-01-直连复现.cmd`**。

### 方式 B：命令行

```powershell
cd <本仓库根目录>
.\运行-PS-01-直连复现.cmd
# 或
powershell -ExecutionPolicy Bypass -File .\PS-01-直连复现.ps1
```

脚本会自动完成：

```
=== 0. 环境准备 ===        启动 Docker Desktop，等引擎就绪
=== 1. kind 集群 ===        建集群（已内置镜像加速），或复用已有集群
=== 2. cert-manager ===     KServe 前置依赖
=== 3. KServe v0.17.0 ===   OCI chart 装 kserve-crd / resources / runtime-configs
                            + 创建 sklearn ClusterRuntime
=== 4. 容器镜像 ===         经镜像源拉取 → docker save → 导入 kind 节点
=== 5. 部署 ISvc ===         等 READY=True
=== 6. 推理验证 ===          port-forward + POST /v1/models/...:predict
```

成功的样子：

```
  [OK] ISvc READY=True
  [OK] HTTP 200  {"predictions":[1,0,1]}

NAME           URL                                       READY   AGE
sklearn-iris   http://sklearn-iris-default.example.com   True    69s
pod/sklearn-iris-predictor-765f5d85fb-hstnb             1/1     Running
deployment.apps/sklearn-iris-predictor                   1/1     Available
service/sklearn-iris-predictor                           ClusterIP 10.96.151.4
horizontalpodautoscaler.autoscaling/...                  cpu: <unknown>/80%
```

`{"predictions":[1,0,1]}` 是鸢尾花数据集的分类结果（setosa / versicolor / virginica），正确。

### 常用参数

| 参数 | 作用 |
|---|---|
| `-SkipCluster` | 集群已存在时跳过创建 |
| `-FreshCluster` | 先删掉旧集群再重建 |
| `-ClusterName xxx` | 换集群名（默认 `kserve-demo`） |
| `-WithPortMapping` | 把 30080/30081 映射到宿主机（**默认不开**，见坑 6） |

## 五、版本二 · 离线复现

前提：集群 + KServe 已装好（先跑一次版本一）。

```powershell
.\运行-PS-02-离线复现.cmd
```

它做的事：**不连任何外网**——

- 容器镜像从本地 tar 导入（`docker save` 出来的归档）
- 模型从本地 `model-v2.joblib` 挂进节点，走 `pvc://` 直挂，**根本不创建 init 容器**
- 推理结果与版本一完全一致

> 本包**不含**那个 183 MB 的镜像归档（体积太大不便传输）。需要时自己生成：
>
> ```powershell
> docker pull docker.m.daocloud.io/kserve/sklearnserver:v0.17.0
> docker tag docker.m.daocloud.io/kserve/sklearnserver:v0.17.0 kserve/sklearnserver:v0.17.0
> docker save -o sklearnserver.tar kserve/sklearnserver:v0.17.0
> ```
>
> 把 `sklearnserver.tar` 放到 `中间产物\` 目录下即可；放不放都行，
> 不放时脚本会自动退回用镜像源拉取。

## 六、六个必踩的坑（都已在脚本里修掉）

### 坑 1 · `configmap://` 这个协议在 KServe 里根本不存在

```
Warning  InternalError  StorageURI not supported: storageUri, must be one of:
[gs://, s3://, pvc://, file://, https://, http://, hdfs://, webhdfs://, oci://, hf://]
StorageUri [configmap://xxx] is not supported
```

KServe 只认上面那十种协议，**没有 `configmap://`**。
而且这个校验发生在**准入阶段**——ISvc 会被直接拒绝，Deployment 都不会被创建。

### 坑 2 · `READY` 显示 `Unknown` 和 `False` 是两回事

| 显示 | 含义 |
|---|---|
| `Unknown` | **准入就被拒**了，Controller 压根没开始协调（坑 1） |
| `False` | 准入过了，但 Pod 没起来（镜像拉取失败 / init 容器崩溃） |

先看 `kubectl describe isvc <name>` 的 **Events** 段，能直接定位是哪一类。

### 坑 3 · `https://` 的模型地址必须指向**真实文件**，不能是目录

`storage-initializer` 对 `http(s)://` 只做**单文件 GET**。
GCS 的"目录前缀"（`.../model`）不是一个真实对象，GET 它必然 404：

```
Storage initialization failed: HTTP resource not found at 'https://storage.googleapis.com/.../model'
```

正确写法要带文件名：

```yaml
storageUri: "https://storage.googleapis.com/kfserving-examples/models/sklearn/1.0/model/model.joblib"
```

> bucket 是 `kfserving-examples`（不是 `kfserving-samples`，后者 403）。

### 坑 4 · `docker cp` 到 kind 节点的 `/tmp` 会"成功但文件看不见"

kind 节点的 `/tmp` 是 **tmpfs 挂载**，`docker cp` 写进去的是被挂载遮蔽的 rootfs 路径，
`docker cp` 返回 **exit 0**，但 `docker exec ls /tmp` 什么都看不到。

**解法**：拷到 `/var/lib` 这类真实目录。

### 坑 5 · `kind load docker-image` 在只有 amd64 的机器上会失败

```
ERROR: failed to load image: ... ctr: content digest sha256:xxx: not found
```

它内部用 `ctr --all-platforms` 导入，而本地只有 amd64 的层。
**解法**：`docker save` → `docker cp` → 节点内 `ctr images import`（**不加** `--all-platforms`）。

### 坑 6 · kind 配置里写死 `hostPort` 会撞端口

```
Bind for 0.0.0.0:30080 failed: port is already allocated
```

本 demo 推理走 `kubectl port-forward`，**根本不需要端口映射**。
脚本默认不开；确实要用 Ingress 直连再加 `-WithPortMapping`（且会先检查端口是否被占）。

## 七、网络相关的两条实战结论

### 结论 1 · Docker Hub 在国内基本要靠镜像加速

`registry-1.docker.io` 的 DNS 会解析到黑洞 IP，报 `connection refused`。
本包用的镜像源（**均为国内第三方公共加速站**，非本地服务）：

| 地址 | 运营方 |
|---|---|
| `docker.m.daocloud.io` | DaoCloud |
| `docker.1ms.run` | 毫秒镜像 |
| `docker.1panel.live` | 1Panel |
| `hub.rat.dev` | 社区维护 |
| `quay.m.daocloud.io` | DaoCloud（代理 quay.io） |

这些是 Docker Hub 的**反向代理缓存**，代理的仍是官方镜像，**digest 与官方一致**。
生产环境建议自建 Harbor；学习/本机用没问题。

**节点侧的加速配置**（脚本建集群时已内置，也可用 `中间产物\apply-ctr-mirror.sh` 手动给已有集群打）：

```
/etc/containerd/certs.d/docker.io/hosts.toml
/etc/containerd/certs.d/quay.io/hosts.toml
+ /etc/containerd/config.toml 里 config_path = "/etc/containerd/certs.d"
+ systemctl restart containerd
```

自测：拉一个没缓存过的镜像，应该 200ms 级完成。

### 结论 2 · GitHub releases 的 CDN 被限速到 ~1.6 KB/s

```
curl: (28) Operation timed out after 30371 milliseconds
       with 49152 out of 986843 bytes received
```

所以 **cert-manager 不要从 GitHub 下载 YAML**，脚本改走 Helm 官方源
（`https://charts.jetstack.io`，实测 2.5 秒拉完）：

```powershell
helm repo add jetstack https://charts.jetstack.io --force-update
helm install cert-manager jetstack/cert-manager --version v1.16.1 `
  -n cert-manager --create-namespace --set installCRDs=true
```

cert-manager 的镜像在 **quay.io**（不是 Docker Hub），所以节点的 containerd 还要额外给 quay.io 配加速。

## 八、写 PowerShell 脚本时自己踩的坑（Windows 中文环境特有）

### `.ps1` 必须是 UTF-8 **带 BOM**

不带 BOM 的 UTF-8 `.ps1` 在中文 Windows 上按 **GBK** 解析，中文全变乱码，直接语法报错
（`Unexpected token '"'`）。反过来，**脚本里写 YAML 要用不带 BOM 的 UTF-8**：

```powershell
[System.IO.File]::WriteAllText($Path, $Content, (New-Object System.Text.UTF8Encoding($false)))
```

### `.cmd` 必须纯 ASCII

cmd.exe 按系统 ANSI 代码页（中文 Windows = GBK/936）解析批处理文件。
`.cmd` 里写中文 → 每行都被切碎，报错长这样：

```
'demo' is not recognized as an internal or external command
```

**解法**：`.cmd` 内全部用 ASCII，中文交给 `.ps1` 输出；开头加 `chcp 65001` 让 PowerShell 的中文正常显示。
另外 `.cmd` 里引用中文名 `.ps1` 也有风险，用通配符绕开：

```bat
set SCRIPT=
for %%f in ("%~dp0PS-01-*.ps1") do set SCRIPT=%%f
powershell -NoProfile -ExecutionPolicy Bypass -File "%SCRIPT%" %*
```

> 本包两个 `.cmd` 已按 **纯 ASCII + CRLF** 交付。
> 只写 ASCII 还不算稳：`.cmd` 用 **LF 换行**在部分 Windows 上也会出问题，
> 一律存成 CRLF 最保险。

### `kind` 建了多个集群时，`kubectl` 会打到别的集群去

`kind create cluster` 会自动把 kube context 切过去，但**复用已有集群**时不会切。
本机要是还留着别的 kind 集群，`kubectl get nodes` 查的就是那个集群，
KServe 的前置检查会莫名其妙地失败（"KServe controller 未就绪"）。

**解法**：脚本里显式切一次 context，本包 PS-01 / PS-02 已内置：

```powershell
Invoke-Native $kubectl @('config','use-context',"kind-$ClusterName") '切换 kube context'
```

手动跑的话：

```powershell
kubectl config use-context kind-kserve-demo
```

### `$Args` 是 PowerShell 自动变量，别拿来当参数名

```powershell
param([string]$Exe, [string[]]$Args)   # ❌ 与自动变量冲突
$out = & $Exe @Args 2>&1              # ❌ 展开失效，命令收到空参数
```

症状极具迷惑性：命令**不报错**，而是打印自己的帮助信息。改名 `$ArgList` 即可。

### 原生 exe 往 stderr 写一行就可能中断脚本

`$ErrorActionPreference='Stop'` 时，PowerShell 5.1 会把原生命令的 stderr 当异常。
稳妥写法是包一层，显式看退出码：

```powershell
function Invoke-Native {
    param([string]$Exe, [string[]]$ArgList, [string]$What = '命令')
    $prev = $ErrorActionPreference
    $ErrorActionPreference = 'Continue'
    try { $out = & $Exe @ArgList 2>&1; $code = $LASTEXITCODE }
    finally { $ErrorActionPreference = $prev }
    if ($code -ne 0) { throw "$What 失败 (exit $code)`n$($out -join "`n")" }
    return $out
}
```
