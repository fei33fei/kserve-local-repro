## 🐛 错在哪

你写的：
```bash
docker cp /c/Users/<你的用户名>/Downloads/model.joblib kserve-demo-control-plane:/model.joblib
# ...
storageUri: "file:///model.joblib"
```

`docker cp ... kserve-demo-control-plane:/model.joblib` 把文件**塞进了 kind 容器的文件系统**（在宿主机外面）。
但 storage-initializer 跑在 K8s Pod 里，Pod 有**自己的容器文件系统**——它**看不到** kind 节点上的 `/model.joblib`，除非我们用 hostPath 把它挂进来。

所以「文件明明在节点上，Pod 就是找不到」是必然结果。

---


## ✅ 方案 A：ConfigMap（推荐，最简单）

> 思路：把模型文件整个塞进 ConfigMap（K8s 原生资源），KServe 的 storage-initializer 会自动把它当作模型目录。sklearn iris 模型只有几 KB，完全够用。

### 第 1 步：删除之前一直 CrashLoopBackOff 的失败实例
```bash
kubectl delete isvc sklearn-iris --ignore-not-found
```
> 旧 Pod 跑了几小时没成功（看到 `Restart Count: 39`），别让它干扰新部署。

<user>@<host> MINGW64 ~$ kubectl delete isvc sklearn-iris --ignore-not-foundinferenceservice.serving.kserve.io "sklearn-iris" deleted


### 第 2 步：把模型打包成 ConfigMap
**先在 Git Bash 里确认文件下载到哪了**：
```bash
ls -lh /c/Users/<你的用户名>/Downloads/model.joblib 2>/dev/null || \
ls -lh ~/Downloads/model.joblib 2>/dev/null || \
echo "❌ 没找到文件，请检查下载位置"
```

找到文件后，执行：
```bash
kubectl create configmap sklearn-iris-model \
  --from-file=model.joblib=/c/Users/<你的用户名>/Downloads/model.joblib \
  -n default
```

验证 ConfigMap 创建成功：
```bash
kubectl get configmap sklearn-iris-model -n default -o yaml
```
应该看到 `data.model.joblib:` 下面有一长串 base64 内容。

### 第 3 步：改 YAML，用 ConfigMap URI
```bash
cat > sklearn-isvc.yaml << 'EOF'
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: sklearn-iris
  namespace: default
spec:
  predictor:
    model:
      modelFormat:
        name: sklearn
      runtime: kserve-sklearnserver
      storageUri: "configmap://sklearn-iris-model"
EOF
```

### 第 4 步：部署并观察
```bash
kubectl apply -f sklearn-isvc.yaml
kubectl get isvc sklearn-iris --watch
```

**预期状态变化**：
- `Pending` → （十几秒后）→ `Ready`，`READY=True`

## 🛟 方案 B：hostPath PV（如果方案 A 失败再用）

> 思路：在 kind 节点上挂载一个目录，然后通过 PersistentVolume 暴露给 Pod。**适合文件比较大（>1MB，ConfigMap 有 1MB 限制）的场景**。

### 第 1 步：在 kind 节点上建目录、放文件
```bash
docker exec kserve-demo-control-plane mkdir -p /mnt/models
docker cp /c/Users/<你的用户名>/Downloads/model.joblib kserve-demo-control-plane:/mnt/models/model.joblib
```

### 第 2 步：创建 hostPath PV
```bash
cat > model-pv.yaml << 'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: model-pv
spec:
  capacity:
    storage: 100Mi
  accessModes:
    - ReadOnlyMany
  hostPath:
    path: /mnt/models
    type: Directory
  persistentVolumeReclaimPolicy: Retain
EOF

kubectl apply -f model-pv.yaml
kubectl get pv model-pv
```

### 第 3 步：改 YAML，用 PVC URI
```bash
kubectl delete isvc sklearn-iris --ignore-not-found

cat > sklearn-isvc.yaml << 'EOF'
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: sklearn-iris
  namespace: default
spec:
  predictor:
    model:
      modelFormat:
        name: sklearn
      runtime: kserve-sklearnserver
      storageUri: "pvc://model-pv/model.joblib"
EOF

kubectl apply -f sklearn-isvc.yaml
kubectl get isvc sklearn-iris --watch
```

测试方法同方案 A 第 5 步。

## 🔍 通用排错命令（任何一步卡住都用得上）

```bash
# 看 Pod 状态
kubectl get pods -n default

# 看具体 Pod 详情
kubectl describe pod -l serving.kserve.io/inferenceservice=sklearn-iris

# 看 storage-initializer 日志（最常用）
kubectl logs -l serving.kserve.io/inferenceservice=sklearn-iris -c storage-initializer

# 看主推理容器日志
kubectl logs -l serving.kserve.io/inferenceservice=sklearn-iris -c kserve-container

# 看 ISvc 状态（关注 Conditions 字段）
kubectl describe isvc sklearn-iris
```

**常见错误信息 → 原因对照**：

| 日志报错 | 原因 | 解决 |
|---|---|---|
| `HTTP resource not found` | 在线 URL 失效 | 用本指南的离线方案 |
| `configmap ... not found` | ConfigMap 名写错 / namespace 不对 | 检查 `kubectl get cm -A` |
| `pvc ... not bound` | PV 没建好 / 没匹配 | `kubectl get pv,pvc` 检查 |
| `Permission denied` | 目录权限问题 | 看 hostPath 路径是否正确 |
