
### 成功执行的有效命令总结及注释

**1. 工具安装**
```bash
# 下载 kubectl 可执行文件
curl -LO "https://dl.k8s.io/release/v1.30.0/bin/windows/amd64/kubectl.exe"
# 将 kubectl 放到系统 PATH 路径下，方便全局调用
mv kubectl.exe ~/.local/bin/kubectl.exe
# 设置环境变量，使当前终端立刻生效
export PATH="$HOME/.local/bin:$PATH"

# 下载 kind 可执行文件
curl -Lo ./kind.exe https://kind.sigs.k8s.io/dl/v0.23.0/kind-windows-amd64
# 移动并赋予执行权限
mv ./kind.exe ~/.local/bin/kind.exe && chmod +x ~/.local/bin/kind.exe

# 下载 Helm 压缩包并解压
curl -LO https://get.helm.sh/helm-v3.15.2-windows-amd64.zip
powershell -command "Expand-Archive -Path helm-v3.15.2-windows-amd64.zip -DestinationPath ."
# 移动 Helm 可执行文件
mv windows-amd64/helm.exe ~/.local/bin/helm.exe
```

**2. 集群与底层依赖**
```bash
# 拉取 k8s 节点镜像（防止 kind 创建集群时卡死）
docker pull kindest/node:v1.30.0

# 用自定义配置创建 kind 集群（包含端口映射）
kind create cluster --name kserve-demo --config kind-config.yaml

# 部署 cert-manager（KServe 依赖它来管理证书）
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.16.1/cert-manager.yaml

# 阻塞等待 cert-manager 启动完毕
kubectl wait --for=condition=Available --timeout=300s deployment/cert-manager -n cert-manager
kubectl wait --for=condition=Available --timeout=300s deployment/cert-manager-webhook -n cert-manager
```

**3. KServe 安装 (OCI 模式)**
```bash
# 创建专用命名空间
kubectl create ns kserve
# 通过 OCI 仓库安装 CRD（资源定义）
helm install kserve-crd oci://ghcr.io/kserve/charts/kserve-crd --version v0.17.0 --namespace kserve
# 安装控制器，并指定为 RawDeployment 模式（轻量级）
helm install kserve-resources oci://ghcr.io/kserve/charts/kserve-resources --version v0.17.0 --namespace kserve --set kserve.controller.deploymentMode=RawDeployment
```

**4. 模型运行时与部署**
```bash
# 应用自定义的 sklearn 运行时配置（解决控制器找不到 runtime 的问题）
kubectl apply -f sklearn-runtime.yaml

# 部署模型服务
kubectl apply -f sklearn-isvc.yaml

# 检查是否创建成功
kubectl get crd | grep kserve
```

### 新开 Git Bash 的恢复与继续步骤（含排错）

下次开机，打开 Git Bash 后，**按顺序执行以下操作**：

#### 1. 检查环境与集群状态
```bash
# 1. 确保 Docker 正在运行，kind 集群状态为 Ready
kubectl get nodes 
```
*如果提示 `The connection to the server ... was refused`，说明 Docker 没启动或者 kind 集群没跑起来。请在 Docker Desktop 界面里把容器启动起来，或者重新执行 `kind create cluster --name kserve-demo --config kind-config.yaml`。*

#### 2. 准备本地模型（彻底解决网络下载失败）
```bash
# 1. 在浏览器下载这个文件：
# https://github.com/kserve/kserve/raw/master/docs/samples/v1beta1/sklearn/v1.0/model/model.joblib
# 2. 假设你把 model.joblib 下载到了 C:\Users\<你的用户名>\Downloads\ 目录下，将其复制到 kind 集群的节点里：
docker cp /c/Users/<你的用户名>/Downloads/model.joblib kserve-demo-control-plane:/model.joblib
```
*(注意：Git Bash 里 Windows 的 C 盘路径是 `/c/...`)*

#### 3. 修改部署文件并重新部署
```bash
# 1. 覆盖生成新的 YAML，指向本地文件
cat > sklearn-isvc.yaml << 'EOF'
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: sklearn-iris
  namespace: default
spec:
  predictor:
    model:
      modelFormat:
        name: sklearn
      runtime: kserve-sklearnserver
      storageUri: "file:///model.joblib"
EOF

# 2. 删除之前的错误实例
kubectl delete isvc sklearn-iris

# 3. 重新部署
kubectl apply -f sklearn-isvc.yaml

# 4. 观察状态（按 Ctrl+C 退出）
kubectl get isvc sklearn-iris --watch
```

#### 4. 如果依然报错（排错方案）
```bash
# 查看 Pod 状态
kubectl get pods -n default

# 如果 Pod 不在 Running，查看详细事件
kubectl describe pod -l serving.kserve.io/inferenceservice=sklearn-iris

# 如果卡在 Init:Error，查看 storage-initializer 的日志
kubectl logs -l serving.kserve.io/inferenceservice=sklearn-iris -c storage-initializer

# 如果主容器 CrashLoopBackOff，查看主容器日志
kubectl logs -l serving.kserve.io/inferenceservice=sklearn-iris -c kserve-container
```

#### 5. 测试推理（看到 READY=True 后）
**新开一个 Git Bash 窗口**，执行端口转发：
```bash
kubectl port-forward svc/sklearn-iris-predictor 8080:80
```
回到**原来的窗口**，执行测试请求：
```bash
curl -X POST http://localhost:8080/v1/models/sklearn-iris:predict \
  -H "Content-Type: application/json" \
  -d '{"instances": [[6.8, 2.8, 4.8, 1.4]]}'
```
如果返回类似 `{"predictions": [2]}`，大功告成！

#### 6. 最终清理（截图存档后，释放资源）
```bash
kind delete cluster --name kserve-demo
```
